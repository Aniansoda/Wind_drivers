# Wind Driver — модуль ядра Android ARM64 (wind.ko)

[中文](README.md) | [English](README.en.md) | [日本語](README.ja.md) | **Русский** | [한국어](README.ko.md)

Чтение и отладка памяти на уровне ядра для Android / Linux ARM64
Один модуль `wind.ko`, одиннадцать подсистем, одно пространство опкодов, три транспорта
Маршрут без CRC, пять семейств точек останова одновременно, все символы вне whitelist разрешаются во время работы

## Что изменилось в этой версии

| Опкод | Было | Стало |
|---|---|---|
| `0x26..0x2B` | трассировка ветвлений ETM/PTM | **точка наблюдения за данными** `wrpbp` |
| `0x38..0x3D` | резерв | удалено, не определяется |
| `0x50..0x55` | — | **Маскировка против обнаружения ACE**, 10 бит / 11 kprobe |
| `0x0C / 0x0D` | наследие ETM | восстановлены старые **BRK** `brk_set` / `brk_clear` |
| `0x33` | — | `OP_STATS`, статистика кэшей |
| `0x34 / 0x37` | — | `HWBP_SET_REGS` / `HWBP_REFRESH` |
| `0x35 / 0x36` | — | `PTEBP_SET_REGS` / `PTEBP_REFRESH` |
| `0x3E / 0x3F` | — | `BP_DIAG` / `BP_ALL_OFF` |
| Гироскоп | одна постоянная точка выполнения | точка выполнения для поиска, затем **переход на стационарный WRP**, правка X/Y, Z вне окна |
| Символы | прямые ссылки | 32 символа вне whitelist разрешаются через `register_kprobe` во время работы |
| Совместимость | `#ifdef` разбросаны по коду | единый `compat.h`, одно дерево исходников от 5.10 до 6.18 |

ETM удалён: Coresight требует, чтобы SoC включила свои тактовые домены и funnel, покрытие устройств низкое, а сами данные он не наблюдает
Коды `0x26..0x2B` отданы WRP; структура конфигурации осталась 24 байта, как у старого `ETMBP_POINT_CONFIG`, поэтому старые бинарники не смещаются

## Транспорты

Три транспорта используют одно пространство опкодов и один диспетчер `wind_dispatch_ioctl`
Выбор по параметру `transport` и результатам зондирования при загрузке

| transport | Транспорт | Механизм | Замечания |
|---|---|---|---|
| 3 | приватный протокол netlink | регистрируется приватный номер `AF_NETLINK`; из пространства пользователя `socket(AF_NETLINK, SOCK_RAW, 31)` и отправка `WIND_NL_MSG` | по умолчанию, узлов в `/dev` и `/proc` нет, объекты ядра не изменяются |
| 2 | приватный misc-символ | `misc_register` | не трогает `/dev/null` и rodata, лучшая совместимость, цена — один узел устройства |
| 1 | подмена fops у `/dev/null` | `inode->i_fop` направляется на копию в модуле | только как резерв, требует `allow_fops_hook=1`, на части устройств есть записи о зависаниях и перезагрузках |

Константы netlink

```
юнит по умолчанию 31      WIND_NL_DEFAULT_UNIT
магия сообщения 0x574E4C31 WIND_NL_MAGIC  ("WNL1")
база опкодов 0x574E0000    WIND_OP_BASE
принимаемый диапазон       WIND_OP_BASE + 0x01 .. WIND_OP_BASE + 0x3F
```

Опкоды вне диапазона отбрасываются без ответа, чтобы случайный ввод не был глубоко разыменован диспетчером

### Параметры модуля

| Параметр | Тип | По умолчанию | Действие |
|---|---|---|---|
| `transport` | int | 3 | `3` netlink, `2` misc, `1` /dev/null i_fop |
| `install_hook` | bool | 1 | ставить хук транспорта при загрузке; `0` — только разрешение символов |
| `allow_fops_hook` | bool | 0 | разрешить подмену `inode->i_fop` у `/dev/null` |
| `hook_level` | int | — | для бисекции: `0` выкл, `1` только fops, `2` fops и ioctl/mmap, `3` сохранить исходный `.open` |

```bash
insmod wind.ko transport=3 install_hook=1
insmod wind.ko transport=0            # только загрузка, без транспорта, для диагностики
```

## Как устроено

### 1 Сессия

Один `OP_BIND` после открытия кэширует ссылку на `task_struct` в `driver_session`
Дальше обращения не идут через `find_get_pid` + `get_pid_task`, экономя один поиск по хэшу pid и две операции со счётчиком ссылок
`session_destroy` освобождает ссылку при закрытии
`mm` не кэшируется: `get_task_mm` вызывается на каждую операцию, поэтому `exec` с подменой `mm` не оставляет висячий указатель

### 2 Доступ к памяти

**Одиночное чтение и запись** один ioctl обслуживает непрерывный диапазон, транслируя постранично

**Пакет** один ioctl несёт N отдельных адресов, N точечных обращений сводятся к одному syscall
Захват `mm` один на пакет, поэтому N пар `mmgrab`/`mmput` становятся одной; при многопоточном опросе заметно падают нагрузка на CPU и конкуренция за блокировки

**mmap без копирования** физические страницы цели отображаются в адресное пространство вызывающего через `remap_pfn_range`, дальше обычный доступ по указателю без ioctl, удобно для больших выборок

**Два режима чтения**

| Режим | Реализация | Плюс | Минус |
|---|---|---|---|
| `MODE_FAST` | `phys_to_virt` + `memcpy` | быстро, не греется | обнаруживается через побочные каналы кэша |
| `MODE_SAFE` | `ioremap_nocache` + `__flush_dcache_area` | без кэша, устойчив к побочным каналам | медленнее, греется |

**Кэш отображений страниц** переиспользует существующие отображения физических страниц, счётчики попаданий и вытеснений читаются через `OP_STATS`

**Кэш трансляций VA→PA** избавляет от повторного обхода таблиц страниц, счётчики `tr_hits` / `tr_misses`

**Обработка swap** при `!pte_present` (swap entry или отсутствие отображения) используется `get_user_pages_remote(FOLL_GET)`, чтобы подкачать страницу по fault чтения, затем трансляция повторяется
Именно `FOLL_GET`, а не `FOLL_WRITE`, чтобы не вызывать COW на отображениях только для чтения

**Корректность на границе страниц** разбиение по `PAGE_SIZE - (addr & (PAGE_SIZE-1))`, каждый сегмент транслируется отдельно

**Исправление алиасов кэша** после записи в память цели GPU / ION буферы могут вернуть старое значение и погасить экран
Обычная RAM читается напрямую через линейное отображение (тот же WB-кэш, что у таблиц страниц процесса; на ARM64 PIPT индексируется физически), а после записи `__flush_dcache_area` возвращает данные в память

### 3 База модуля

`OP_MODULE_BASE` проходит `vm_area_struct` целевого `mm` по имени модуля и возвращает базу загрузки его ELF
До 6.1 список обходится вручную, с 6.1 используется итератор VMA по maple tree, выбор через `KH_HAVE_VMA_ITER` в `compat.h`
`get_module_base` используется и внутри ядра

### 4 Скрытие

**Скрытие файлов** хук на `filldir64` (с откатом на `filldir`), в `pre_handler` имя элемента заменяется на `.` с `namlen=1`
Сопоставление по basename, до 16 записей

**Скрытие процессов** тот же хук сверяет элементы из чистых цифр, до 64

**Скрытие в kgsl** скрывает pid на стороне GPU kgsl, работает вместе с `kgsl_hook_install`

**Снятие** `OP_UNHIDE_ALL` очищает обе таблицы сразу

Почему kprobe В Android GKI 5.x+ есть kCFI и rodata только для чтения, правка пролога функции роняет CFI или защиту записи
kprobe регистрирует колбэк через механизм точек останова и не пишет в код, поэтому CFI обходится структурно

Отложенная регистрация символов `hide_*` регистрирует хук при первом вызове по списку кандидатов (`filldir64` → `filldir`), поэтому невидимый символ не ломает загрузку

### 5 Пять семейств точек останова

Общий каркас: слоты + кольцевой буфер записей + постраничное чтение, плюс диагностика `0x3E` и общий выключатель `0x3F`
Точки выполнения взаимоисключающи: на arm64 всего 4 BRP и 2 WRP

| Семейство | Механизм | Ресурсы | Что в записи | Применение |
|---|---|---|---|---|
| `hwbp` | BRP выполнение / WRP наблюдение через perf | 4 BRP + 2 WRP | PC срабатывания и регистры | входы функций, точки чтения и записи |
| `ptebp` | инверсия атрибутов PTE + теневой трамплин 32 байта | отладочные регистры не нужны | точка срабатывания и управляемые регистры | наблюдение за десятком точек сразу |
| `wrpbp` | точка наблюдения WRP, окно `LEN_8` | 2 WRP | момент записи и вектор | наблюдение за одним полем |
| `brkbp` | инструкция заменена на `BRK`, обработка исключения через kprobe | без аппаратных ресурсов | PC и общие регистры | только запись событий |
| `udpbp` | kprobe на путях UDP | без аппаратных ресурсов | превью полезной нагрузки | наблюдение за ритмом сети |

**hwbp** на arm64 точки выполнения поддерживают только `HW_BREAKPOINT_LEN_4`
При срабатывании PC пишется в запись согласно конфигурации, читается постранично, можно записать обратно с 2-битной маской регистров
`OP_HWBP_SET_REGS` пишет `s3`/`s4`/`s5` прямо из колбэка

**ptebp** инвертирует биты атрибутов PTE для fault, 16 слотов, до 8 страниц на слот
Отладочные регистры не занимает, поэтому работает вместе с `hwbp`
Исходная инструкция исполняется из трамплина — страницы RWX, открытой внутри целевого `mm`
Битовые поля PTE (`PTE_UXN` / `PTE_PXN` / `PTE_RDONLY` / `PTE_VALID` / `PTE_AF`) читаются и пишутся напрямую, после изменения сбрасывается TLB

**wrpbp** окно данных `LEN_8` у `arch_install_hw_breakpoint`
Обработчик забирает значение из `perf_event` в запись, `OP_WRPBP_SET_VEC` пишет обратно с 2-битной маской
На этом слое стоит стационарный режим гироскопа

**brkbp** заменяет инструкцию на `BRK`, принимает исключение, 16 слотов
Аргументы и возвращаемые значения читаются и пишутся из контекста ядра через `wind_read_process_va` / `wind_write_process_va`, без `__user`
Пока только запись событий, без записи в регистры

**udpbp** kprobe на путях UDP в ядре

```
TX  udp_send_skb  ->  ip_send_skb  ->  ip_local_out   берётся первый разрешившийся
RX  __udp4_lib_rcv
```

TX предпочитает `udp_send_skb`, потому что LTO в GKI инлайнит `ip_local_out`
Фильтр по pid, порту и направлению, срабатывания идут в кольцевой буфер и читаются постранично
8 слотов, 256 записей на слот, превью 32 байта
Только IPv4, `__udp6_lib_rcv` не подключён

**Старый brk** `OP_BRK_SET` / `OP_BRK_CLEAR` реализуют одиночную точку выполнения через `register_user_hw_breakpoint`, оставлены для совместимости

**Правка регистров FP** ядро собирается с `-mgeneral-regs-only`, и встроенный ассемблер clang отвергает мнемоники вида `stp q3,q4,[x9]`
`hwbp_fp_reg_direct` использует `.inst` с сырыми кодами, базовый регистр фиксирован `x9`

| Инструкция | Код |
|---|---|
| `stp q3, q4, [x9]` | `0xad001123` |
| `str q5, [x9]` | `0x3d800125` |
| `ldp q3, q4, [x9]` | `0xad401123` |
| `ldr q5, [x9]` | `0x3dc00125` |

### 6 Гироскоп

Управление идёт не через инъекцию `/dev/uinput` из пространства пользователя, а хуком выхода BitTube в системной библиотеке

```
целевой символ android::BitTube::sendObjects(sp<BitTube> const&, void const*, size_t, size_t)
кандидаты libsensor.so -> libsensorservice.so -> libui.so
```

Поиск `filp_open` + `kernel_read` читают целевой ELF, смещение символа берётся из `.dynsym`, к нему добавляется база загрузки нужного модуля в целевом процессе
Аргументы `sendObjects` (arm64) `x1` = массив events, `x2` = count; `x0` — это tube, для данных не используется

Две фазы

1. **Поиск** на `sendObjects` ставится точка выполнения; первое срабатывание даёт адрес буфера events
2. **Стационар** точка выполнения сразу снимается, вместо неё ставится точка наблюдения `LEN_8` на `data[0..1]`

В стационаре остаётся один WRP и ни одной точки выполнения внутри system_server, частота падает с «каждого пакета сенсоров» до «каждой записи»
Снятие perf-события из его же обработчика переполнения даёт дедлок, поэтому переключение выполняется в `gyro_set_velocity` (контекст процесса, раз в кадр)

Раскладка события (`sensors_event_t`, 0x68 байт)

```
0x00 version | 0x04 sensor | 0x08 type | 0x10 timestamp
0x18 float data[16] | 0x58 flags
```

Распознаются `SENSOR_TYPE_GYROSCOPE`(4) и `SENSOR_TYPE_GYROSCOPE_UNCALIBRATED`(16)
У обоих x/y/z лежат в `data[0..2]` и правятся одинаково
В NDK `ASensorEvent` поле type смещено на `0x04`, поэтому код сначала пробует `0x08`, затем `0x04`

**Z не меняется структурно**, это не параметр: точка выполнения пишет 8 байт по `+0x18`, окно WRP `LEN_8` покрывает `data[0..1]`, маска клиента `0x3`
`+0x20` (z) не попадает ни в одно окно записи

Защита от рекурсии WRP свой `copy_to_user_nofault` снова задевает точку наблюдения
Ставится двойной барьер: `user_mode(regs)` и per-CPU флаги `gyro_wrp_busy` / `wrpbp_busy`

`gyro_stop` / `gyro_resume` только приостанавливают и возобновляют правку, хук остаётся
`gyro_remove` действительно снимает
Если процесс завершился, `gyro_resume` вернёт `-ESRCH`, если хук не стоял — `-ENODEV`, оба случая идемпотентны

### 7 Теневые страницы и защита записи ядра

**Операции с PTE теневой страницы** `wind_shadow_pte_set` / `wind_shadow_pte_get`
Обход таблиц страниц целевого `mm` до PTE, перезапись как `(old & ~mask) | (val & mask)` со сбросом TLB; используется для бесследных точек и тонкой настройки прав страниц
Поле физического адреса извлекается через `KH_PTE_PA_MASK`, новый PTE собирается через `KH_PHYS_TO_PTE`
На машинах с 52-битным PA старшие два бита лежат в PTE `[9:8]`, поэтому простое `| page_to_phys()` портит запись

**Обход защиты записи образа ядра** `wind_force_kernel_page_rw` / `wind_kernel_page_ro_state`
`set_memory_rw` не принимает адреса образа ядра, поэтому модуль сам идёт по таблице страниц и делает страницу образа записываемой
`ro_state` проверяет весь путь по таблицам и читает AP[2] листа, ничего не записывая

## Работа с символами: без CRC плюс разрешение во время работы

Две опоры; без любой из них модуль не загрузится на реальном устройстве

### Без CRC

После сборки длины секций `__versions` / `__version_ext_crcs` / `__version_ext_names` обнуляются
`check_version()` пропускает сравнение CRC целиком и оставляет один `pr_warn_once`
Присутствующая секция `__versions` заставляет `same_magic(has_crcs=1)` сравнивать только хвост после первого пробела vermagic: `SMP preempt mod_unload modversions aarch64`

| Ядро | Файл | Ветка при пустой таблице версий | Третий аргумент `same_magic` |
|---|---|---|---|
| 5.10.198 | `kernel/module.c` | `Broken toolchain` → `return 1` | `info->index.vers` |
| 5.15.149 | `kernel/module.c` | то же | то же |
| 6.1 | `kernel/module/version.c` | то же | то же |
| 6.6.66 | `kernel/module/version.c` | то же | то же |
| 6.12.58 | `kernel/module/version.c` | то же, плюс ветка ext-таблицы | то же |
| 6.18.21 | `kernel/module/version.c` | то же, плюс ветка ext-таблицы | то же |

Границы маршрут снимает требование «CRC совпадает на каждом устройстве», но не снимает vermagic
Хвост (`SMP preempt mod_unload modversions aarch64`) обязан совпадать побайтово
Поэтому один ko покрывает устройства той же серии с теми же признаками конфигурации и любым префиксом `LOCALVERSION`
Переход между сериями (ko от 6.1 на 6.12) отклоняется с `bad vermagic`
Config по-прежнему должен совпадать с устройством, иначе хэши типов CFI и раскладка структур разойдутся: модуль загрузится и упадёт

Vermagic устройства

```
6.12.58-android16-6-g7704a1ae279b-ab15213644-4k SMP preempt mod_unload modversions aarch64
```

### Разрешение символов во время работы

GKI замораживает KMI, и модуль вендора может ссылаться только на символы из пересечения с whitelist
32 нужные драйверу функции в него не входят, и прямая ссылка даёт

```
wind: Unknown symbol kthread_use_mm (err -2)
```

`err -2` — это ENOENT: имени нет в таблице экспорта, и `insmod` сразу падает
Поэтому все они идут через `sym.c`: `register_kprobe` (в whitelist) разрешает адрес по имени, а при сборке CRC-ссылки не создаются

```
mm/процесс   mmput  kthread_use_mm  kthread_unuse_mm  remap_pfn_range
vmap         __get_vm_area_caller  free_vm_area  vunmap  ioremap_page_range  iounmap
таблицы      set_memory_rw  set_memory_ro  contpte_ptep_get  __arch_clear_user
файлы        filp_open  kernel_read  file_path
устройства   misc_register  misc_deregister
netlink      netlink_kernel_create  __netlink_kernel_create  netlink_kernel_release
             __netlink_kernel_release  netlink_unicast  __alloc_skb
точки        register_user_hw_breakpoint  unregister_hw_breakpoint
             register_wide_hw_breakpoint  unregister_wide_hw_breakpoint
fp           fpsimd_preserve_current_state
nofault      copy_from_user_nofault  copy_to_user_nofault
```

Результаты печатаются при загрузке; при неудаче выводится `wind: ... 未解析到`
Соответствующая возможность деградирует, но загрузка проходит

### Слой совместимости

`compat.h` собирает всё в одном месте, одно дерево исходников от 5.10 до 6.18

| Пункт | Граница | Решение |
|---|---|---|
| `mmap_lock` | 5.8 | `mmap_read_lock` ↔ `down_read(&mm->mmap_sem)` |
| `kmap_local_page` / `kunmap_local` | 5.11 | откат на `kmap_atomic` / `kunmap_atomic` |
| `ptep_get` | 5.10 | при отсутствии `*(ptep)` |
| обход VMA по maple tree | 6.1 | `KH_HAVE_VMA_ITER` |

| `__flush_dcache_area` | 5.11 | встроенная последовательность `dc civac` |

## Диагностика

| Симптом | Куда смотреть |
|---|---|
| `Unknown symbol ... (err -2)` при загрузке | символ не экспортируется, переведите его на разрешение через `sym.c` |
| `disagrees about version of symbol` | CRC не совпадает, используйте маршрут без CRC или пересоберите |
| `version magic ... should be` | не совпадает vermagic |
| После `insmod` нет транспорта | `dmesg`: `transport`, `misc_register`, `netlink` |
| Зависание или перезагрузка после открытия транспорта | используйте `transport=2`, не включайте `allow_fops_hook=1` |
| Читаются устаревшие данные | переключитесь на `MODE_SAFE`, проверьте GPU / ION буферы |
| Скрытие не работает | включён ли `CONFIG_KALLSYMS_ALL`, виден ли `filldir64` |
| Гироскоп не действует | тот ли процесс читает сенсоры, разрешился ли `sendObjects`, взведён ли WRP в `dmesg` |
| Точки не ставятся | сначала `bp_all_off`, затем остаток BRP/WRP в `OP_BP_DIAG` |
| Цель падает после срабатывания теневой страницы | сверьте `KH_PTE_PA_MASK` / `KH_PHYS_TO_PTE` с разрядностью PA устройства |

Ключевые слова в логе

```
wind:
wind: misc_register
wind: netlink
wind: sym use_mm
filldir64
gyro
hwbp / ptebp / wrpbp / brkbp / udpbp
bp: all off
```

## Известные ограничения

- Скрытие зависит от видимости символов; без `CONFIG_KALLSYMS_ALL` `filldir64` не находится
- Транспорт через fops `/dev/null` имеет записи о зависаниях на части устройств, по умолчанию выключен
- Маршрут без CRC снимает только проверку CRC символов, но не хвост vermagic, не CFI и не раскладку структур
- Маршрут без CRC не работает между сериями ядер: ko от 6.1 на 6.12 отклоняется с `bad vermagic`
- `brkbp` только пишет события, записи в регистры нет
- `hwbp` / `ptebp` пока не ограничены TID, срабатывания на весь процесс
- Точки выполнения на arm64 поддерживают только `LEN_4`, инструкция должна быть выровнена по 4 байта
- 4 BRP и 2 WRP — предел аппаратуры; пять семейств одновременно будут конкурировать
- `ptebp` покрывает до 8 страниц на слот, после смены страницы нужен `OP_PTEBP_REFRESH`
- Точки UDP только для IPv4, пути IPv6 не подключены
- Артефакты до 6.12.58 зависят от config и таблицы CRC в `tools/device/`; для другой модели нужен новый сбор
